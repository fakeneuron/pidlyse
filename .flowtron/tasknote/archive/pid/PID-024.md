# PID-024 | tty-sentinel-ssot

[← PLAN.md](../PLAN.md) · 🟢 In progress

## 🎯 Goal

Extract a single `ProcessItem.isTTYAttached(_:)` helper and call it from `ScanEngine.makeItem` so the TTY-sentinel detection lives in one place instead of being duplicated across two sites.

## ✅ Acceptance

- [x] Single source of truth for the TTY sentinel set (`""`, `"??"`, `"?"`, `"-"`) — only `ProcessItem.isTTYAttached(_:)` holds those literals.
- [x] `ProcessItem.hasTTY` delegates to `isTTYAttached(_:)`; behavior unchanged.
- [x] `ScanEngine.makeItem` calls `ProcessItem.isTTYAttached(p.tty)` with no leftover unused `let t`.
- [x] All tests pass (`make test`).

## 🧩 Subtasks

- [x] Add `static func isTTYAttached(_ tty: String) -> Bool` to `ProcessItem` holding the sentinel logic.
- [x] Rewrite `var hasTTY` to call `Self.isTTYAttached(tty)`.
- [x] In `ScanEngine.makeItem`, replace the `let t` + `let hasTTY` inline pair with `let hasTTY = ProcessItem.isTTYAttached(p.tty)`.
- [x] Run `make test`.

## 🔗 Related

- [[PID-16.3]] — `makeitem-alloc` deliberately inlined `hasTTY` into `makeItem` to drop a draft allocation; this task dedups via a static helper without reintroducing that allocation.
