**Discovery Notes:**

`detectKind` lowercases the full argv and walks kind tokens; `npm` is matched by `hasTokenBoundary` (prefix, `/npm `, `.npm.`, or ` npm `). A Claude Code session shell is `/bin/zsh -c source …/shell-snapshots/…` and the `-c` string includes prior commands, so ` npm ` inside that string returns `.npm`. PID-046 fixed substring false positives (`pnpm`, `fake-node`) with the same helper; it did not exclude shell wrappers. No archived note names `shell-snapshot`. Assumption: any shell `-c`/`-lc` whose command contains `shell-snapshot` is the wrapper and is not a stray candidate, even when the inlined text is `node` or `pytest`. A bare `npm` command that merely mentions the directory stays `.npm`.

Best practices: classification stays inside `ScanCore.detectKind`; the early-out is a private predicate next to `isGoRun`, same file, no new type.

**Implementation Notes:**

Early-out `isShellSnapshotWrapper` at the top of `detectKind`, same private-predicate shape as `isGoRun`. A command is a wrapper only when it contains `shell-snapshot`, a delimited shell token (`/bin/zsh`, `/bin/bash`, `/bin/sh `, or a spaced `zsh`/`bash`/`sh`), and `-c`/`-lc`. `/bin/sh` is space-delimited so `/bin/shell-snapshots` does not count. No other kind matching changed.
