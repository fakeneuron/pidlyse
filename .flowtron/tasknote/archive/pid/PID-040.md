# PID-040 | popover-realign

[← PLAN.md](../PLAN.md) · 🟢 In progress · 🔗 [[PID-037.3]]

## 🎯 Goal

Re-anchor the menu-bar popover under the status item whenever its SwiftUI content height changes at runtime, so the arrow/notch stays aligned (it currently drifts when a process disappears while the popover is open).

## ✅ Acceptance

- [ ] When a process disappears while the popover is open (live background scan removes a row, or the last stray closes and the view collapses to the empty state), the popover stays anchored under the status item — the arrow/notch does not drift sideways.
- [ ] Tab switches (Processes ↔ Containers) and row expand/collapse, which also change content height, keep the popover anchored.
- [ ] No regression to open/close behavior, right-click context menu, or the icon pulse.
- [ ] `make test` stays green.

## 🧩 Subtasks

- [ ] Promote the inline `NSHostingController` to a retained `AppDelegate` property.
- [ ] Set `sizingOptions = [.preferredContentSize]` so the SwiftUI intrinsic size drives `preferredContentSize`.
- [ ] Observe content-size changes (KVO on `preferredContentSize`) and, while `popover.isShown`, re-anchor by re-invoking `popover.show(relativeTo:of:preferredEdge:)`.
- [ ] Build and hand off for visual confirmation (menu-bar popover can't be AI-verified).

## 🔗 Related

- [[PID-037.3]] — visual-confirm tasknote that surfaced this bug ("popover notch misaligns when a process disappears").

**Discovery Notes:**

Root cause: `NSPopover` is shown once and not re-anchored. `MenuBarView` height is dynamic — most starkly, the body switches between the fixed-height-360 `content` ScrollView and the small `emptyState` (`MenuBarView.swift:35-39`, `:129`) when the last stray closes; it also varies on tab switch and expand/collapse. The `ScanEngine` timer keeps scanning while the popover is open, so a background scan can remove a row live, the `NSHostingController` resizes the popover, and the arrow drifts out from under the status item.

Fix approach: retain the hosting controller, set `sizingOptions = [.preferredContentSize]` so SwiftUI's intrinsic size propagates, KVO-observe `preferredContentSize`, and re-call `popover.show(relativeTo:of:preferredEdge:)` while shown to force re-anchoring to the button.

**Implementation Notes:**

`Pidlyse/AppDelegate.swift`: promoted the inline `NSHostingController` to a local `hosting`, set `hosting.sizingOptions = [.preferredContentSize]` so SwiftUI's intrinsic size drives the popover, and added a `contentSizeObservation` KVO token on `\.preferredContentSize`. Centralized re-anchoring in a `reanchorPopover()` helper that re-invokes `popover.show(relativeTo: button.bounds, of: button, preferredEdge: .minY)` while shown.

**Corrected root cause (after first visual confirm failed).** The dominant drift is NOT content-height — the Processes list is a fixed-height-360 ScrollView, so dropping one of many rows doesn't resize the popover. The real cause: the status button renders a count badge (` 22`), and `NSStatusItem` is `.variableLength`, so as the count loses digits (and as the open-triggered rescan flips it to the spinner) the button width changes, and — status items being right-edge-pinned — the icon's center slides, leaving the popover anchored to the old bounds.

**Final approach (after second visual confirm: re-anchoring "bounced").** Following the moving icon (re-invoking `show(...)`) correctly kept the arrow aligned but visibly *moved the whole window* on every width change — the user's own diagnosis ("the center of the app is hard to pinpoint"). Switched to **freezing the icon while the popover is open** instead of chasing it: `updateIcon()` early-returns via `guard !popover.isShown`, so the `.variableLength` button never resizes while shown → anchor never moves → no bounce, and the original misalignment is gone too. `popover.delegate = self` + `popoverDidClose` resyncs the icon (count / spinner / clean glyph) once it closes. The live SwiftUI list inside the popover still reflects removals in real time. Removed the re-anchor helper, the `preferredContentSize` KVO, the deferred `show()`, and `animates = false`; kept `sizingOptions = [.preferredContentSize]` for correct vertical sizing (popover width is fixed, so height changes never drift the `.minY` arrow).
