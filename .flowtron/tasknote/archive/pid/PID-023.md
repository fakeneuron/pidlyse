**Discovery Notes:**
- **Current architecture:** `PidlyApp.swift` is a pure SwiftUI `App` with two scenes — `MenuBarExtra { MenuBarView } .menuBarExtraStyle(.window)` and `Settings { SettingsView }`. The icon is `MenuBarIconView` (private struct in `PidlyApp.swift`), a reactive SwiftUI view bound to `engine`. No AppKit `NSStatusItem`/`AppDelegate`/`import AppKit` anywhere in source.
- **Drift check:** Premise accurate. `MenuBarExtra(.window)` does not surface right-mouse events. Note: PID-021 already added an in-popover Quit button (power icon, `MenuBarView.swift:67`), so right-click→Quit is a convenience duplicate — confirmed with user it's still wanted (Medium).
- **Tenet conflict (resolved):** `SPEC.md:12` ("MenuBarExtra … avoids AppKit boilerplate") + CLAUDE.md ("no AppKit") forbid AppKit for the tray. PID-001 (`PID-001.md:84`) established `MenuBarExtra(.window)` as the foundational pattern. User clarified these were soft suggestions → proceed with best-practice AppKit migration; update both docs in Phase 4.
- **Best-practice approach:** Replace `MenuBarExtra` with an `AppDelegate`-managed `NSStatusItem`. Reuse the existing SwiftUI views by hosting them: `NSHostingView(MenuBarIconView)` in the status button (keeps the icon reactive), `NSHostingController(MenuBarView)` as the popover content. Left-click toggles the popover; right-click pops a one-item `NSMenu`.
- **Engine-sharing:** `ScanEngine` moves from `@StateObject` in the App to ownership by `AppDelegate`; the `Settings` scene reads `appDelegate.engine` so both the popover and Settings see the same instance.
- **⚠️ Regression risk (PID-022):** the gear button uses `@Environment(\.openSettings)`. Once `MenuBarView` is hosted in an `NSHostingController` (outside the App scene graph), that environment action may no longer resolve. Must verify in Phase 3; add a fallback if it regresses. This is the main reason for the 🛠️ checkpoint.
- **Downstream-impact scan:** Only open PLAN entries are Future Opportunities. "Animated icon states beyond simple badge" now builds on the `NSStatusItem`/`NSHostingView` icon substrate rather than MenuBarExtra's label — substrate change, not stale/contradictory; no PLAN edit needed. Others (XPC, Docker panel, port-registry JSON, TTY sentinel) unaffected.

**Implementation Notes:**
- **Pattern survey:** No existing AppKit bridge in the app — this is the first. The existing SwiftUI views (`MenuBarIconView`, `MenuBarView`) are reused unchanged via hosting rather than reimplemented, which is the minimal-churn shape. `MenuBarIconView` was relocated from `PidlyApp.swift` (was `private`) into `AppDelegate.swift` (now internal) since the AppDelegate hosts it.
- **New `Pidly/AppDelegate.swift`:** `AppDelegate: NSObject, NSApplicationDelegate` owns `let engine = ScanEngine()`, an `NSStatusItem`, and a transient `NSPopover`. `applicationDidFinishLaunching` embeds `IconHostingView(MenuBarIconView)` in the status button (pinned to all four edges, `variableLength`), sets `popover.contentViewController = NSHostingController(MenuBarView)`, and wires `button.action` on `[.leftMouseUp, .rightMouseUp]`.
- **Click routing:** `handleClick` reads `NSApp.currentEvent?.type` — `.rightMouseUp` → `showContextMenu` (one-item `NSMenu` "Quit Pidly" → `NSApplication.terminate`, shown via `menu.popUp`); else → `togglePopover`.
- **`IconHostingView`** (private `NSHostingView<MenuBarIconView>` subclass) overrides `hitTest` → `nil` so the display-only icon never swallows clicks; the `NSStatusBarButton` owns all click handling.
- **`PidlyApp.swift`:** now just `@NSApplicationDelegateAdaptor(AppDelegate.self)` + a `Settings { SettingsView(engine: appDelegate.engine) }` scene; `MenuBarExtra` scene removed. Engine ownership moved from the App's `@StateObject` to the AppDelegate so the popover and Settings share one instance.
- **`Pidly.xcodeproj/project.pbxproj`:** registered `AppDelegate.swift` (IDs `B132`/`B133`) in all four sections (PBXBuildFile, PBXFileReference, PBXGroup, PBXSourcesBuildPhase).
- **Docs:** `SPEC.md` (Tech Stack bullet + Project Structure listing) and `CLAUDE.md` (tech-stack bullet) updated to record the `NSStatusItem` bridge replacing the "no AppKit / MenuBarExtra" stance.
- No new unit tests: the change is UI/AppKit plumbing with no pure-logic surface; `ScanEngine` classification is unchanged and stays covered.
