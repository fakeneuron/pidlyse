# PID-063 | Docker scope — metrics-only vs functionality trim

[← PLAN.md](../../PLAN.md) · 📌 Sidequest (filed 2026-08-08)

## Idea

Operator wouldn't use Pidlyse to kill docker/container processes — they'd use Docker Desktop. The app currently carries a Containers tab, a docker dropdown in the processes menu, and docker kill/stop/restart plumbing. Explore trimming the noise: keep docker surfaces for metrics only? Drop them entirely? Or keep functionality because *other* users may value in-app container actions? Product-scoping decision — weigh maintenance cost of `DockerService`/`DockerCore`/container UI against actual use.
