# PID-039 | npm-surface-dedup

[← PLAN.md](../PLAN.md) · ✅ Completed · 🔗 [[PID-13.3]]

## 🎯 Goal

Disambiguate how `npm` processes surface in the UI so the same `npm` no longer reads as duplicated — appearing both as its own row/group and nested under a parent (e.g. playwright).

## ✅ Acceptance

- [ ] A scanned npm/npx wrapper with exactly one scanned child collapses to a single row, grouped + labeled by the child's kind (playwright-mcp / Vite / Node), no longer doubled.
- [ ] The merged row's kill button targets the wrapper (tree root) PID so the whole subtree dies; PID-reuse start-time check validates against the root.
- [ ] A wrapper with no scanned child (orphaned `npm run dev`), or with >1 scanned child, is left unchanged (no merge, no PID-id collision).
- [ ] The "child of npm" provenance hint no longer appears (wrapper is no longer a scanned parent).
- [ ] Merge logic lives in `PidlyseCore` (`ScanCore`), is pure/injectable, and is covered by tests; `make test` green.

## 🧩 Subtasks

- [ ] Add pure `ScanCore.collapseWrappers(_:)` + private `isNpmWrapper(_ command:)` helper — detect npm/npx wrapper parents with exactly one scanned child; replace the pair with a merged `ProcessItem`: identity (pid/ppid/tty/startTime/elapsed) from the root wrapper, command/kind/riskTier from the child, cpuPercent+rssKB summed across the pair.
- [ ] Call `collapseWrappers` as the final step of `ScanCore.enumerate` (after ignore/dismiss filters).
- [ ] Add `ScanEngineTests` cases: npm-exec-playwright pair → one `.playwrightMCP` row, pid = wrapper; npm-run-dev+vite → one `.vite` row; wrapper w/ no scanned child → unchanged; wrapper w/ 2 scanned children → unchanged (no merge); non-wrapper parent → unchanged.
- [ ] `make test` + build; visual confirm in the popover.

**Discovery Notes:**

**Reproduced against live `ps -axww` output (2026-06-29).** Two distinct manifestations, one root cause: `npm`/`npx` wrapper processes surface as independent rows alongside the "real" matched child.

1. **playwright-mcp doubles *within* its own group.** `npm exec @playwright/mcp@latest --headless …` contains the substring `@playwright/mcp`, so `ScanCore.detectKind` (ScanCore.swift:130-134) classifies the *wrapper* as `.playwrightMCP` before the `npm` token check (line 145) ever runs. Its `node …/.bin/playwright-mcp` child is *also* `.playwrightMCP`. → two `playwright-mcp` rows per MCP instance (confirmed: PIDs 105/160, 19669/19702, 32988/33062, …). This is the most jarring "looks duplicated" symptom.

2. **`npm run dev` shows as a standalone `npm` row beside the real server.** `npm run dev` → `.npm`; its child `node …/.bin/vite` → `.vite`, or `…/next` / `…/astro` → `.node`. One logical dev server renders as two rows in two different groups (confirmed: 66996/67014 bananapeel vite, 61570/61586 fakeneuron next, 51641/51657 sciphoenix astro). The child row's expansion even reads "child of npm".

**Source map:**
- `ScanCore.detectKind` (ScanCore.swift:127-149) — ordered if-chain; `@playwright/mcp` wins before `npm`.
- `ScanCore.parentCommand` (ScanCore.swift:80-83) — already resolves a scanned child→parent relationship within the result set. Reusable signal for "is this row's parent also a scanned candidate?".
- `MenuBarView.grouped` (MenuBarView.swift:322-327) — flat per-`kind` grouping; no notion of parent/child.
- `ProcessItem.ppid` — carried on every item; the tree linkage is already available.

**Archive skim:** PID-13.3 (process-patterns) added the vite/bun/node kinds + the `detectKind` ordering this builds on. PID-036.3 added the "child of <parent>" provenance hint via `parentCommand` (the linkage I'd reuse). No prior tasknote addressed wrapper/child de-duplication. No drift — all cited paths/functions current.

**Key design tension for collapsing a wrapper+child pair:**
- *Informative identity* favors the **child** (`node …/playwright-mcp`, `vite`) — more specific label.
- *Kill-the-whole-tree* favors the **parent/root** (`npm exec …`, `npm run dev`) — killing it takes down the subtree; killing only the child orphans the wrapper, which then reappears next scan.

**Operator decision (AskUserQuestion):** Approach = **Merge into one row**; Kill target = **tree root (wrapper)**.

**Resolved implementation shape:** Merge lives in `ScanCore` (pure, testable; per CLAUDE.md "all scan + classification logic in PidlyseCore"). The merged `ProcessItem` takes its **identity from the root wrapper** (pid/ppid/tty/startTime → kill + PID-reuse check hit the root) but its **kind/command/riskTier from the child** (so it groups + labels as playwright-mcp/Vite/Node) — matching the accepted preview ("PID 105  node …/playwright-mcp"). CPU+RAM summed across the pair. Side effects: the "child of npm" hint disappears (symptom 2 hint), and a child's port hint keyed by the child PID is no longer surfaced on the merged row (minor degrade — the cwd project label already answers "which app").

**Merge guard:** only the 1:1 case (wrapper with exactly one scanned child) merges, to keep row `id` (= pid) unique and kill semantics unambiguous. All observed real trees are 1:1.

Discovery surfaced an approach decision (merge + kill-root) → fire 🛠️ before Phase 2.

**Implementation Notes:**

**Pattern survey:** Extended `ScanCore` as a pure post-filter step, mirroring the existing `ignoredNames`/`dismissedPIDs` filters that run at the tail of `enumerate`. No new type or field — the merged row is a plain `ProcessItem` whose fields are composed from the wrapper + child. `parentCommand` (PID-036.3) already demonstrated the "look up a relationship within the scan set" shape; `collapseWrappers` reuses the ppid linkage.

**Changes:**
- `ScanCore.swift`: added `collapseWrappers(_:)` (public, pure) + `isNpmWrapper(_:)` (private). Called as the final step of `enumerate` (replacing `return all`). Merged item = wrapper identity (pid/ppid/tty/startTime/elapsed) + child kind/command/riskTier + summed cpu/rss. 1:1 guard via `childrenByPPID` count.
- `ScanEngineTests.swift`: new `ScanCoreWrapperCollapseTests` class — 6 tests (npm-exec-playwright merge keeping wrapper identity + summed RAM/CPU; npm-run-dev+vite merge; no-child unchanged; 2-children unchanged; non-wrapper parent unchanged; end-to-end through `enumerate`).
- No `MenuBarView` / `KillService` changes needed — grouping (`grouped` by kind), the kill path (`item.pid` + `item.startTime`), and "Clean all safe" all consume the post-collapse `engine.items` transparently.
