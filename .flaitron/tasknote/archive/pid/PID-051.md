### Debug Log

**Expected vs Observed:**
- *Expected:* Killing one Chrome (playwright-mcp) helper drops that one row; the rest of the list stays put.
- *Observed:* The whole list appears to clear momentarily, then a respawned batch repopulates.

**Hypotheses (ranked):**
1. ~~`engine.scan()` clears `items` (sets it empty) mid-scan, causing a render flash.~~ **FALSIFIED.** `scan()` (ScanEngine.swift:116–155) computes the new result on a background queue and assigns `items` **atomically** on the main queue (line 147). The only other mutation is `dismiss()` removing one PID (line 161). `items` is never set to `[]` during a scan. (confidence was High; disproven by reading the code)
2. ~~SwiftUI re-renders the whole list because row identity is unstable per scan.~~ **FALSIFIED.** `ProcessItem.id == pid` (ProcessItem.swift:107) is stable; unchanged PIDs diff in place. Groups sort deterministically (PID-50.3). No structural whole-list teardown at the render layer.
3. **The "momentary clear" is real process data, not a flicker bug. SURVIVES.** Killing one Chrome renderer makes Chrome tear down its whole helper cohort; the post-kill rescan fires ~2 s after the click — right after the SIGKILL grace period (`KillService.killPosix` schedules `onComplete` at `.now() + gracePeriod`, gracePeriod = 2 s, KillService.swift:13/125–130) — which lands squarely in the teardown trough. The respawned helpers are caught only by a *later* scan (auto-timer at `scanInterval`, default 120 s, or the `onAppear { engine.scan() }` on the next popover open, MenuBarView.swift:53). So "clear → repopulate" is **two scans observing two genuine states of Chrome**, not one scan flashing.

**Minimal repro (operator-run — GUI + live Chrome, can't run headless here):**
1. Start playwright-mcp so a Chrome (playwright-mcp) helper cohort is running.
2. Open the Pidlyse popover; confirm the Chrome (playwright-mcp) group shows several helper rows.
3. Kill one helper row.
4. Watch the list over the next few seconds.

**Repro outcome:** Pending operator confirmation of the visual; the code-level mechanism is confirmed (hypothesis 3). The decision on whether to suppress the trough is an operator call — see the question raised below.
