**Discovery Notes:**

- **Design fork (PLAN offers "keys, or the whole `ScanRequest` + `protectedProjects` load"):** doing the load. Keys-only would leave the parse chain duplicated, and the parse chain is the other half of CLI parity. The load can't return just a `ScanRequest`: the app's editors bind the *raw* lines (`ignoredNames: [String]`, `protectedProjects`), and `elapsedThreshold` must distinguish "unset" from a saved value. So `ScanSettings` carries the raw saved values and exposes `request` (parsed) for the CLI.
- Shape: `SettingsKey` enum of five `static let` strings; `ScanSettings { elapsedThreshold: TimeInterval?; ignoredNames: [String]; disabledKinds: Set<ProcessKind>; customRules: [CustomRule]; protectedProjects: [String] }`, `static func load(from: UserDefaults) -> ScanSettings`, `var request: ScanRequest` (threshold defaulting to `ScanCore.defaultElapsedThreshold`).
- Behavior to preserve: a saved threshold `<= 0` is treated as unset (both consumers today); the CLI's missing-suite case (`UserDefaults(suiteName:)` returns nil) degrades to defaults — `main.swift` maps the optional suite through `ScanSettings.load(from:)` and falls back to an empty `ScanSettings()`.
- The write side stays in `ScanEngine`'s `didSet`s (the app owns persistence) but now uses `SettingsKey.*`, so a rename is one edit and the round-trip test catches a half-rename.
- Assumptions: no `project.pbxproj` edit (SPM core, per PID-079.6 note); no migration needed — the key *strings* do not change, and a test pins them; no AGENTS.md convention line change expected beyond a possible one-clause mention at closure.
- No clarifications needed — the one fork (keys-only vs whole load) is resolved above on the PLAN line's own wording; reversible at review.
- Phase-1 exit: Discovery surfaced no significant deviation → skip 🛠️.
