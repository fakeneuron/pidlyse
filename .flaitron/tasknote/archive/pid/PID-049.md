**Final Summary:**

Surveyed five comparable tools (live web research) — the direct competitor **PortKiller**, plus zkill, Sloth, Stats, iStat Menus. Finding: Pidlyse already matches or leads the direct competitor on its core safety + provenance story; the harvestable gains are small power-user affordances + one real detection gap. Below is the conservative, high-confidence shortlist (deliverable). **This is a survey only — nothing is committed to PLAN.md here.** Triage into concrete tasks (likely `/ft-epic-discovery`) is the operator's follow-on step.

### 📋 Prioritized shortlist (triage candidates)

**Tier 1 — clear wins, low-regret, no new shell-out / security surface**

1. **Row context menu** (right-click a process row) — Copy PID · Copy command line · Copy `kill <pid>` · Reveal in Activity Monitor · Reveal cwd in Finder. *Why it fits:* pure additive power-user nicety every mature tool has (Sloth); uses `NSWorkspace`/pasteboard only — no new shell-out. *Effort:* small. *Risk:* low.
2. **Sort control for the process list** (by age / CPU% / RAM). *Why it fits:* directly serves the core "find the runaway memory hog" job (cf. the "Claude Code ate 14 GB" zombie-killer narratives); all data already on `ProcessItem`. *Effort:* small. *Risk:* low.
3. **Reclaimable-footprint summary in the popover header** — e.g. "8 strays · 3.2 GB reclaimable". *Why it fits:* sums existing `rss`; motivating, ties to the memory-reclaim story; zero new data. *Effort:* small. *Risk:* low.

**Tier 2 — strong, slightly more involved**

4. **Quick filter field in the popover** — type to filter rows by command / project / port (native `.searchable`). *Why it fits:* Sloth/Stats staple; most valuable when many candidates are listed. *Effort:* small–medium. *Risk:* low. *Caveat:* lower payoff than in Sloth since Pidlyse already lists only matched strays.
5. **Per-kind scan toggles in Settings** — discoverable on/off per process kind (e.g. never flag `node`/`bun`), upgrading today's free-text "ignored substrings". *Why it fits:* Stats' per-module toggle pattern; cuts noise and marginally speeds scans (no-bloat/performant posture). *Effort:* medium. *Risk:* low.
6. **Keyboard navigation in the popover** — arrow-key row selection, ⌘⌫ to kill the selected safe row, Esc to close. *Why it fits:* native menu-bar power-user speed. *Effort:* medium. *Risk:* low–medium (SwiftUI focus management in an `NSPopover` can be fiddly).

**Tier 3 — genuine gap, but carries one architectural cost (flagged)**

7. **Brew-services awareness** — detect `brew services` infra (postgres / redis / mysql) and surface it demoted to *Needs review* (never an easy kill), same as Docker/registered-port infra. *Why it fits:* the one real detection gap vs PortKiller; matches Pidlyse's "real infra → needs review" model. *Effort:* medium. *Risk / caveat:* **adds a new `brew` shell-out to the deliberately narrow injection-free surface** (`/bin/ps`, `/usr/sbin/lsof`, `docker` only) — would have to replicate the path-pinned, ownership-verified binary discipline from `DockerService`/`KillService`. This is the only proposal with a real cost against the security posture; triage accordingly.

### 🚫 Considered and rejected (kept out to preserve the no-bloat posture)

- **System-wide resource monitoring** (CPU/GPU/temp/network graphs, à la Stats / iStat Menus) — different mission; would dilute the focused hygiene tool. Strong reject.
- **Framework-name row labels** ("Node (Next.js)", "Java (Spring Boot)", à la PortKiller) — Pidlyse's git-project/cwd label already gives *better* identity; marginal gain for added command-parsing bloat.
- **Dedicated "what's listening on port X" lookup** (à la zkill/PortKiller) — duplicates the existing inline registered-port provenance hint.
- **Extra menu-bar icon animation / icon reordering / localization** (à la Stats) — bloat for a focused personal tool.

**Suggested triage:** Tier 1 (items 1–3) is a tidy `/ft-epic-discovery` cohort or three quick `[light]` tasks. Tier 2 each stand alone. Tier 3 (#7) wants its own explicit decision given the security-surface cost.
