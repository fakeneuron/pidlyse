  No clarifications needed (--unattended). Assumptions: (1) **Decision: registered-port rows stay out of the sweep.** A stray verdict only says no terminal or app holds the process; a dev server on a port the operator reserved in the port registry is the case where that signal is least trustworthy (detached `nohup` / launchd services look identical), and killing it loses live state while skipping it costs one ✕ click. This is the same asymmetry that keeps high-risk rows per-row. It also restores the documented PID-005 invariant. The opposite choice (leave behaviour, document it) would sweep the one class the registry exists to protect. (2) "Port-bound" means the row or any tree member listens on a registered port, via the scan's `listeningPorts` map (registered ports only). (3) Not a bucket or tier change: an overlay like 🔒, applied in the sweep predicate only, so the verdict, badge counts, and Likely-strays listing are unchanged. (4) Rows that are port-bound and also non-high-risk are the only ones affected in practice, since `.node` / `.uvicorn` / `.docker` / `.llmServer` are already high.
