# PID-094 | url-clean-gate

[← PLAN.md](../PLAN.md) · ✅ Completed · 🔗 [[PID-58.2]] · [[PID-58.1]]

## 🎯 Goal

Stop `pidlyse://clean` from killing processes on any URL open without an explicit in-app user action, and make README §Security name every non-click kill trigger.

## ✅ Acceptance

- [x] `URLScheme` no longer has a `.clean` verb: `pidlyse://clean` / `pidlyse:clean` parse to `nil`, and `scan` still routes. Verified by `swift test --package-path Packages/PidlyseCore --filter URLSchemeTests`
- [x] `AppDelegate.application(_:open:)` routes `scan` only; the now-dead `ScanEngine.fireCleanResultNotification` is removed. Verified by `make test` (app target compiles, and the whole suite passes)
- [x] README §Security no longer claims "every kill is an explicit click" without qualification, and it names every non-click kill trigger: the Shortcuts / Spotlight "Clean Likely Strays" action (Raycast's Shortcuts listing too), the CLI `clean` / `kill`, and the Raycast scripts. It also says the URL scheme cannot kill. Verified by `grep -n "Clean Likely Strays\|pidlyse clean\|Raycast\|pidlyse://" README.md`, plus `judgment` (the wording is prose)
- [x] No doc still advertises `pidlyse://clean` (README Integrations, SPEC.md integrations table and prose, `PidlyseApp.swift` comments). Verified by `grep -rn "pidlyse://clean" README.md SPEC.md AGENTS.md Pidlyse Packages/PidlyseCore/Sources` → only historical or "removed" mentions
