**Discovery Notes:**

### Shared design surface inventoried

- **`Pidlyse/KillService.swift:145-164`** — `findContainerID(for: pid)`: the F9 smell. Per-kill it runs `docker ps -q` + bulk `docker inspect --format "{{.Id}}\t{{.State.Pid}}"`, then matches scanned PID against `State.Pid`. The single bulk inspect already dodges per-container round-trips, but it re-runs on every kill click. The `.2` cache moves this resolution to scan time and has `findContainerID`/`dockerStopByPID` consume it.
- **`Packages/PidlyseCore/.../DockerCore.swift` + `Pidlyse/DockerService.swift`** — the canonical pure-parse / impure-shell-out split (CLAUDE.md non-negotiable). New PID→name parsing lands in `DockerCore`; the `docker inspect` shell-out lands in `DockerService` (alongside `listContainers()`).
- **`Pidlyse/ScanEngine.swift:19,89-117`** — `@Published listeningPorts: [Int32: Set<Int>]` populated inside `scan()`'s background block and assigned on the main queue. The container-owner map mirrors this exactly: a new `@Published containerOwners: [Int32: String]` resolved once per scan.
- **`Pidlyse/MenuBarView.swift:270-283`** — the PID-036.3 provenance-hint block in the row expansion (`:5173 listening`, `child of <cmd>`), expansion-gated, `.caption2`/`.secondary`, rendered only when resolvable (graceful degrade). The `.3` UI adds a fourth line: `owned by container <name>`.
- **`Packages/PidlyseCore/.../ScanCore.swift:73-83`** — `parentCommand(ofPPID:in:)` is the resolver precedent: a pure static lookup the UI calls per row. The container-owner lookup will instead read the pre-resolved `ScanEngine` map (docker access is impure, so it can't be a pure ScanCore resolver).
- **SPEC/README contract** — display vocabulary documented in `SPEC.md` + `README.md` (per PID-036.4 audit). The new `owned by container <name>` phrasing should be added there in the `.3` child.

### Archive precedents (load-bearing)

- **`PID-036.1/.2/.3/.4`** — direct parent. Cohort shape `.1 discovery → .2 provenance-core → .3 hints-ui`; PID-EPIC-037 deliberately mirrors it. PID-036.4 audit recorded the docker deferral and the F9 gating rationale verbatim — this epic is the planned continuation.
- **`PID-28.1/.2`** — established the `DockerCore`/`DockerService` split and `listContainers()`; the `.2` owner-cache extends the same module boundary.
- **`PID-35.3`** — scan-time identity capture (`startTimeProvider` plumbed through `ScanCore.enumerate`); precedent for threading a scan-time-resolved value, though here the map lives on `ScanEngine` (app side) since docker access is app-side.

### Drift / viability caveat

- **macOS VM matching** — on Apple Silicon, containers run in the LinuxKit VM; `docker inspect State.Pid` is a VM-internal PID and container-internal processes don't appear in the host `ps` scan. So the host-PID→container match (same mechanism as `dockerStopByPID`) may resolve only for the narrow set of cases the kill path already handles. **Resolved (see table): proceed with graceful-degrade** — the hint renders only when a PID matches, exactly like the port/parent hints; no false promise when it can't resolve.

### Resolved scoping

| Question | Resolution |
|----------|------------|
| macOS VM match viability | **Proceed, graceful-degrade** — build cache + hint on the existing match mechanism; render nothing when no PID matches (same contract as port/parent hints). |
| Child split | **`.2` owner-cache + `.3` ownership-ui** — `.2` includes refactoring `findContainerID` to consume the shared cache (retires F9). N=4 holds; audit stays `.4`. |
| Display phrasing | `owned by container <name>` (matches the deferred line + the `child of <cmd>` / `:N listening` vocabulary). Defaulted, not separately gated. |
