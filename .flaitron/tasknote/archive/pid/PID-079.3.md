# PID-079.3 | shell-run-timeout

[← PLAN.md](../PLAN.md) · ✅ Completed · 🔗 [[PID-EPIC-079]]

## 🎯 Goal

Give `Shell.run` a per-caller deadline so a stuck `ps`, `lsof`, or `docker` cannot wedge a scan, and a timed-out scan still publishes and clears `isScanning`.

## ✅ Acceptance

- [x] `Shell.run` terminates a child that outlives its deadline and returns `("", false)`, discarding partial stdout — `swift test --package-path Packages/PidlyseCore --filter ShellTests`
- [x] Every `ps`, `lsof`, and `docker` spawn passes that tool's `Shell.Budget` (`ps` 10s, `lsof` 20s, `docker` 20s) — `rg -n "Shell\\.run\\(" -g '*.swift' Packages/PidlyseCore/Sources`
- [x] A scan whose shell calls expire still publishes and clears `isScanning` — `xcodebuild test -scheme Pidlyse -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO -only-testing:PidlyseTests/ScanEngineTimeoutTests`

## 🧩 Subtasks

- [x] Add a required `timeout` to `Shell.run`, with `Shell.Budget` for ps / lsof / docker
- [x] On expiry, SIGTERM the direct pid, SIGKILL if it is still alive, return `("", false)` and drop partial stdout
- [x] Pass the budgets from every existing `Shell.run` call site
- [x] Prove `/bin/sleep` dies (`ESRCH`) and a forced-expiry scan publishes an empty process table with `isScanning` false

Extended `Shell.run` rather than adding a second spawn helper. Callers still own the binary and the args; they now also pass the tool budget. `ScanEngine.scan`'s publish path is unchanged. `init(defaults:)` defaults to `.standard` so the app is unchanged and the test can avoid the user's suite (a short saved interval would fire the timer while `XCTest` pumps the run loop).

A first review (blocker) said the sleep test's time bound did not prove the child died, and an empty `items` array did not prove the scan's shells expired. Fixed: the sleep test records the pid and asserts `ESRCH`; the scan test asserts `processTable` is empty, which a live `ps -axo` cannot produce. A later note that `setpgid` after `Process.run()` returns fails with `EACCES` was fixed by deleting that path — production tools are direct execs, and the tests use `exec` so the launched pid is the sleeper.
