## 📝 Phase 1: Discovery

- [x] Reviewed the task entry in PLAN.md

- [x] **Relevance Assessment**

  **Verdict:** Proceed
  **Rationale:** Bug confirmed in current code. With `expected == nil`: a recycled PID gives `current` = the bystander's token, SIGTERM fires, `startSnapshot = current` matches on re-read, so SIGKILL fires too. A gone PID gives `current == nil`, SIGTERM hits ESRCH (unchecked), escalation declines, and the call returns `.confirmed`, so a non-kill gets logged as a clean.

- [x] Read relevant source files — `KillCore.swift`, `ScanPipeline.swift:85-97`, `ScanCore.swift:240` (token = `startTimeProvider.flatMap { $0(p.pid) }`), `Killability.swift:80-87`, `KillCoreTests.swift:89-151`

- [x] **Best Practices Review** — The change is a one-branch flip inside an existing pure decision function, and the impure `killPosix` already maps `false` to `.notKilled`. No new abstraction, and dependency direction is unchanged.

- [x] **Archive skim** — `archive/pid/` (README: `PID-*` → `archive/pid/`) hits: PID-35.3, 35.6, 53.2, 57.1, 57.2, 62.2. PID-35.3 L84 is the origin of the permissive choice, made so that "a wiring miss can never silently no-op every kill".
