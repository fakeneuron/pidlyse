# PID-069 | respawn-per-identity-watches

[← PLAN.md](../PLAN.md) · ✅ Completed · 🔗 [[PID-62.5]]

## 🎯 Goal

Give `RespawnHistory` one watch per killed identity instead of one per signature, and have `ScanEngine.kill` ask whether each kill respawned. That way same-signature rows killed in separate clicks can't share or overwrite one respawn verdict.

## ✅ Acceptance

- [x] Two same-signature kills armed before the follow-up scan both stay open. A later kill no longer replaces an earlier one's watch, so the earlier kill's respawn is still detected. — `make test` (new `RespawnHistoryTests` case)
- [x] One new process claims at most one watch, including across separate scans. A comeback already claimed by kill A can't also mark kill B respawned on B's own follow-up scan. — `make test` (new cases)
- [x] `ScanEngine.kill` gets the per-kill verdict from a `RespawnHistory` query keyed by the killed identity. The baseline/`unclaimed` count-diffing is gone. — `grep -c 'unclaimed\|respawnCount' Pidlyse/ScanEngine.swift` → 0 (narrowed from `baselines`, which also matches an unrelated header comment about dismissal baselines)
- [x] Existing respawn behaviour is unchanged: signature-wide `isRespawner` / `respawnCount`, the detection window, the sibling rule, and the unknown start time rule. — `make test` (existing `RespawnHistoryTests` pass unchanged)
- [x] SPEC.md's respawn definition matches the per-identity model. — `grep -q 'per killed identity\|each verified kill' SPEC.md` (judgment on wording)

## 🧩 Subtasks

- [x] `RespawnHistory`: replace the `[Signature: Watch]` map with a list of per-identity watches (identity = pid + start time). Persist the identities that already claimed a watch and the killed identities that respawned, pruned to the detection window. Add `didRespawn(pid:startTime:)`.
- [x] `recording`: go through the open watches newest kill first. Each one claims one eligible, unclaimed observation, which counts the respawn per signature and records the killed identity.
- [x] `ScanEngine.kill`: drop `signatures` / `baselines` / `unclaimed`. After the follow-up scan, mark a `.gone` row `.respawned` if `didRespawn` is true for its identity.
- [x] Tests: separate-click overwrite, shared comeback across two scans, and the `didRespawn` per-identity query.
- [x] Update the doc comments (`RespawnHistory`, `ScanEngine.kill`) and the SPEC respawn paragraph.

**Discovery Notes:**

- Matching order: watches have nested eligibility, since a respawn must start at or after `killedAt`. Newest kill first means a later kill never loses its only candidate to an earlier kill that had others available.
- Claimed-identity pruning: an observation that started before `now - detectionWindow` can't match any open watch, so claimed entries older than that can be dropped. `didRespawn` records are pruned by their kill time against the same window. The engine queries right after its follow-up scan, well inside it.
- Batch case (PID-62.5 blocker 3) stays covered: two same-signature targets in one click each get their own watch, and one comeback claims only one.
